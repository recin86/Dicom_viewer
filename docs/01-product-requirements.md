# DICOM Viewer 제품 요구사항

이 문서는 개인 연구용 macOS 로컬 뷰어의 사용 목적과 기능 범위를 정의한다. 우선 CT/MR/X-ray/US 자료를 정확하게 열고 탐색하는 앱을 만들고, 측정과 작업 저장 기능을 추가한다. 세부 DICOM 지원은 [DICOM 지원 명세](03-dicom-support.md), 검증 방법은 [개발과 검증 계획](06-development-and-validation.md)을 따른다.

문서 버전 0.2 · 작성·검토일 2026-09-30 · 상태 검토·보완한 설계 초안. 아래 버전별 범위와 우선순위는 제안이다.

## 사용 목적

주 사용자는 집의 Mac에서 DICOM 자료를 열어 비교하고 연구에 활용한다. 기본 흐름은 폴더 선택, 검사와 시리즈 탐색, 영상 조작, 측정, 작업 저장과 재개이다. 기본 열람과 연구 작업은 인터넷 연결 없이 수행한다.

범용성은 우선 여러 제조사와 촬영 장비에서 나온 표준 DICOM을 명시된 범위 안에서 처리한다는 뜻으로 정의한다. 한 모델의 Mac이나 한 샘플 파일에 종속된 구현을 피한다. macOS 외 운영체제의 앱 구현은 현재 범위 밖이며, Rust 코어가 OS UI에 의존하지 않도록 해서 향후 재사용 가능성을 유지한다.

모든 DICOM 객체와 압축 형식을 지원한다는 약속은 하지 않는다. 공개 지원 목록에는 실제 검증한 조합을 기록한다.

## 사용자 시나리오

| ID | 상황 | 완료 상태 |
| --- | --- | --- |
| UC-01 | 여러 검사 자료가 있는 폴더를 연다 | 읽을 수 있는 검사와 시리즈가 나타나고, 일부 파일 실패는 별도로 확인 가능 |
| UC-02 | CT 또는 MR을 연속해서 살펴본다 | 올바른 스택을 선택하고 빠르게 이동하며 위치와 방향을 확인 |
| UC-03 | X-ray를 확대하고 밝기를 조절한다 | 종횡비를 유지하며 관심 부위를 탐색하고 원래 표시로 복원 |
| UC-04 | US 정지 영상과 cine를 본다 | 컬러를 유지해 표시하고 재생, 정지, 프레임 이동 가능 |
| UC-05 | 두 시리즈를 비교한다 | 각 뷰에 시리즈를 배치하고 활성 뷰를 구분하며 독립 조작 가능 |
| UC-06 | 연구용 측정과 메모를 남긴다 | 원본 프레임에 연결된 결과와 단위를 저장하고 다시 열 수 있음 |
| UC-07 | 이전 작업을 이어간다 | 파일이 존재하면 프레임과 표시 상태를 복원하고, 없으면 위치 재지정 가능 |
| UC-08 | 지원하지 않는 자료를 만난다 | 파일 실패의 이유와 가능한 동작을 확인하고 다른 자료를 계속 탐색 |

## 버전별 범위 제안

**v0.1은 기본 열람과 연구 작업의 완성 버전**으로 제안한다. 내부 개발 단계에서는 표시 가능한 빌드를 먼저 만들고 측정과 저장을 이어 붙인다. v0.1의 DICOM 범위는 지원 명세의 기본 목표 항목이며, 모든 네 가지 modality의 모든 변형을 포함하지는 않는다.

| 범위 | 기능 |
| --- | --- |
| v0.1 기본 열람 | 파일과 폴더 열기, 검사와 시리즈 목록, 회색조와 컬러, CT/MR 스택, 지원 코덱의 US cine |
| v0.1 조작 | 확대, 이동, window/level, 반전, 90도 회전과 뒤집기, 표시 초기화, 태그 조회 |
| v0.1 비교와 연구 | 1/2/4분할, 독립 비교, 거리와 각도, 사각형과 타원 ROI, 메모, 프로젝트 저장, CSV와 현재 뷰 PNG 내보내기 |
| v0.2 후보 | Enhanced CT/MR의 다차원 해석, MPR, 공간 위치 연동, US 영역 보정 측정 |
| 후속 후보 | 볼륨 렌더링, 고급 segmentation, DICOM SR/SEG/Presentation State 읽기와 쓰기, PACS/DICOMweb |

대표 자료에 Enhanced CT/MR이나 특정 코덱이 많으면 P0에서 버전 범위를 조정한다. 범위 조정은 지원 명세와 시험 자료 목록에도 반영한다.

## 기능 요구사항

| ID | 요구사항 | v0.1 완료 조건 |
| --- | --- | --- |
| FR-01 | 로컬 파일과 폴더 입력 | 열기 창과 드래그 앤 드롭으로 읽고 하위 폴더를 탐색하며 진행과 취소 지원 |
| FR-02 | 검사와 시리즈 분류 | UID 기반 분류, 중복과 충돌 감지, 실패 파일 요약, 점진적 목록 갱신 |
| FR-03 | 프레임 표시 | 지원 범위의 회색조와 컬러를 올바르게 표시하고 실패를 빈 정상 영상으로 표시하지 않음 |
| FR-04 | 공간과 시간 탐색 | CT/MR 스택과 US 시간 시퀀스를 구분하고 프레임 수 및 현재 위치를 정확히 표시 |
| FR-05 | 영상 조작 | 픽셀 종횡비를 유지하고 window/level, 확대, 이동, 반전, 회전, 뒤집기, 초기화가 원본과 측정 좌표를 훼손하지 않음 |
| FR-06 | 메타데이터 조회 | 기본 오버레이와 검색 가능한 태그 패널, 긴 값과 대용량 값의 제한 표시 |
| FR-07 | 비교 화면 | 1/2/4개 뷰에 시리즈 배치, 활성 뷰 구분, 기본 조작은 활성 뷰에 적용 |
| FR-08 | 측정과 ROI | 보정 근거에 맞는 거리와 각도, 회색조 ROI 통계, 단위와 유효 픽셀 수 표시 |
| FR-09 | 주석과 메모 저장 | 프레임 식별자와 좌표를 포함해 저장하고 저장 상태 및 실패를 표시 |
| FR-10 | 작업 복원 | 시리즈, 프레임, 표시 상태, 주석 복원과 누락 파일 재연결 |
| FR-11 | 결과 내보내기 | 측정 CSV와 현재 뷰 PNG를 선택한 위치에 저장하고 내용과 단위를 확인 가능 |
| FR-12 | 견고한 실패 처리 | 손상 파일, 미지원 형식, 파일 이동, 메모리 부족에서 원인과 복구 동작 제공 |

FR-08의 US 물리 측정은 v0.1의 필수 완료 조건에서 제외한다. v0.1에서 US는 주석과 픽셀 단위 측정을 제공할 수 있으나 cm/mm 결과로 오인되지 않도록 표시한다. RGB 영상의 ROI 밝기 통계는 기본 제공하지 않는다.

| ID | 요구사항 | 판단 기준 |
| --- | --- | --- |
| QR-01 | 표시와 수치의 정확성 | 픽셀, 방향, 좌표, 단위와 변환을 기준 자료 및 독립 계산과 비교 |
| QR-02 | 조작 반응성 | 디코딩 중에도 UI가 응답하고 오래된 요청이 현재 화면을 덮지 않음 |
| QR-03 | 자원 사용 제한 | 디코딩 동시성, CPU/GPU 캐시와 최대 입력 크기를 제한하고 메모리 압박에 대응 |
| QR-04 | 원본 보존과 오프라인 사용 | 열람·측정·저장으로 원본 DICOM 바이트가 바뀌지 않고 기본 기능에 네트워크 불필요 |
| QR-05 | 작업 복구 | 저장 실패와 버전 불일치를 감지하고 마지막 유효 프로젝트를 복원 가능 |
| QR-06 | 지원 범위의 재현성 | OS, CPU, 앱과 코덱 버전 및 시험 자료를 기록하고 동일 조건에서 결과 재현 |
| QR-07 | 로컬 자료 처리 | 일반 로그에는 환자명, 환자 ID, 원문 태그와 전체 파일 경로를 기본 기록하지 않음 |

정량 목표는 [검증 계획](06-development-and-validation.md)의 성능 및 정확성 항목에서 관리한다. 아직 측정한 성능이나 달성한 결과는 없다.

## 데이터와 사용 정책 제안

원본 DICOM은 사용자가 선택한 위치에서 읽고, 앱 인덱스와 연구 프로젝트는 별도로 저장한다. 파일을 앱 저장소로 복사하는 라이브러리 모드는 후속 후보이다. 목록에서 자료를 제거하는 기능과 원본 파일 삭제는 구분하며, v0.1에는 원본 삭제 기능을 넣지 않는다.

프로젝트에는 프레임 식별 정보, 주석과 연구 메모가 들어간다. 표시용 환자 정보 숨김은 기본 검사 목록·시리즈 라벨·영상 오버레이의 환자명과 환자 ID에 적용한다. 태그 패널의 원문 값, 파일 이름·경로, 자유 메모와 픽셀에 포함된 문자는 이 설정으로 제거되지 않는다. 이 범위를 설정에서 설명하며 DICOM 비식별화 기능으로 표현하지 않는다. PNG에 포함될 오버레이는 내보내기 전에 별도로 선택할 수 있게 한다.

## 첫 버전의 범위 밖

- PACS 접속, 네트워크 수신 서버, 사용자 계정과 클라우드 동기화.
- 진료 판독 업무의 운영 요건, 보고서 작성과 병원 시스템 연동.
- 모든 제조사 private tag의 의미 해석과 모든 DICOM SOP Class 지원.
- Windows/iOS 앱, 3D 볼륨 렌더링, 자동 병변 분석.

이 목록은 향후 확장을 금지하지 않는다. 초기 구조에 별도 서비스, 계정 시스템 또는 사용하지 않는 플러그인 계층을 미리 도입하지 않는 범위 기준이다.

## 요구사항을 확정할 때 확인할 내용

최소 macOS, Intel 지원 여부, 추가 코덱, Enhanced CT/MR의 우선순위, 연구 데이터 저장 형식은 [문서 안내의 미결정 목록](../README.md)에 모아 관리한다. 새로운 요구사항은 해당 목록 또는 FR 항목에 반영한 후 개발 단계와 시험을 연결한다.
