# DICOM 시험 자료와 독립 기대값

프로젝트 루트는 `../../..`이다. `AGENTS.md`, `docs/06-development-and-validation.md`의 시험 자료 관리·최소 구성·정확성·해당 T 항목과 `docs/03`·`docs/04`의 해당 의미를 읽는다. 메인이 배정한 파일만 작성한다.

## 사례 설계

요구사항과 실패 가능 경계에서 사례를 고른다. 배정된 T 항목마다 정상 결과, 경계·잘못된 입력·의도된 미지원 중 필요한 경우를 정한다. 작은 합성 자료는 명확한 계산값을 위한 것이며 제조사·코덱 호환성 자료를 대신하지 않는다.

`docs/06`의 합성 사례는 초기 기대값 근거다. 문서의 입력과 식을 독립 계산으로 확인하고 fixture에 실제 기록된 태그·배열이 그 입력과 일치하는지 읽어서 검증한다. 불일치하면 메인에게 근거를 보고하고 합격 기준을 임의로 고치지 않는다.

## Golden 값의 근거

- 픽셀과 Modality 값은 명시한 작은 입력 배열과 독립 계산에서 만든다. 제품 decoder/measurement 함수를 호출한 결과를 그 함수의 정답으로 저장하지 않는다.
- lossless 정수 디코딩은 독립 golden 배열과 모든 픽셀을 비교한다. lossy는 동일 입력의 신뢰할 수 있는 참조 decoder와 사례별 tolerance를 기록한다.
- signedness·endian·rescale/LUT/VOI 단계와 RGB/YBR/Palette의 색변환 유무를 분리한다. 같은 encoder/decoder의 왕복만으로 외부 코덱 호환성을 입증하지 않는다.
- 좌표·단위·각도·ROI는 F64 독립 수식에서 계산하고 불균일/미보정·padding·빈 결과를 포함한다. frame index/number와 trim 전후 시간 근거를 별도로 확인한다.
- 취소·저장 경합은 실행 순서를 제어해 재현한다. 임의 sleep이 우연히 만드는 순서를 유일한 재현 방법으로 삼지 않는다.

## 자료와 manifest

각 fixture에 `docs/06`이 요구하는 ID, 출처와 사용·재배포 조건, content SHA-256, SOP/Transfer Syntax/Modality, 픽셀 형식·크기·프레임, 차원·보정·lossy 상태, 기대 성공·실패와 기대값 근거를 기록한다. decoder·참조 뷰어·생성 도구 버전도 포함한다. manifest의 직렬화 형식은 실제 시험 runner와 맞추고 한 곳에서 관리한다.

재배포 가능한 합성/공개 자료와 외부 로컬 자료를 구분한다. 실제 파일을 받기 전에는 manifest에 실제 해시나 출처를 꾸며 쓰지 않는다. 공개 자료의 라이선스를 확인하고, 로컬 원본·식별 정보·절대 경로를 저장소에 자동 추가하지 않는다. 환자명/ID 태그 제거만으로 burned-in 문자와 전체 비식별 상태가 확인되었다고 보지 않는다.

fixture 생성 후 실제 파일을 다시 읽어 태그·길이·프레임·해시와 기대값이 일치하는지 확인한다. 기대값 파일과 제품 출력 파일의 위치를 분리해 덮어쓰기를 막는다.

## 실행과 결과

작성한 시험이 배정된 최종 구현을 실제로 실행하는지 확인한다. 제품이 없으면 자료 준비 완료만 보고하고 제품 시험은 not-run으로 남긴다. 합격을 위해 tolerance·golden을 실제 결과에 맞추지 않는다.

반환 결과에는 fixture ID·해시·출처·독립 계산/decoder 근거, 관련 FR/QR·T ID, 변경 파일, 실행 결과와 부족한 자료군을 포함한다. 지원 표 갱신과 단계 완료는 메인이 실제 증거로 판단한다.
