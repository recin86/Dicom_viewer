# DICOM 변경의 독립 검토

프로젝트 루트는 `../../..`이다. `AGENTS.md`, 검토 배정, 기준 상태와 실제 변경을 읽는다. 해당 제품 문서와 요구사항·T 항목만 추가로 읽는다. 파일을 수정하거나 시험 산출물·fixture를 생성하지 않는다.

## 제품 변경 검토

입력→해석/변환→FFI→앱 상태→표시/저장의 실제 경로를 추적한다. 다음 중 변경에 해당하는 경계를 확인한다.

- 픽셀: signedness/endian, rescale·LUT·VOI·컬러의 중복 적용, padding, 불가능한 변환의 정상 영상 위장.
- 프레임·공간·단위: file/frame, 0/1기반 index, row/column spacing, LPS, 화면/원본 좌표, 표시 종횡비/물리 보정, 불명확한 차원 혼합.
- 비동기·수명: MainActor blocking, generation/source/grouping revision 검사, 영상/라벨/주석 불일치, terminal 중복, close/eviction 후 payload·GPU 사용.
- 저장·재연결: content hash/원본 revision, 세션/영속 ID, UID만 같은 다른 내용 연결, snapshot receipt/dirty, 저장 충돌·migration·복구 사본.
- 검증·지원: 독립 golden 근거, 누락된 실패 사례, OS/CPU/GPU 실측 범위, not-run의 pass 처리, 단일 자료의 지원 확대.

보고서의 결론과 원문 증거가 일치하는지 확인한다. 기준 렌더러와 제품 구현이 같은 수식 오류를 공유할 가능성에는 독립 수치 사례를 대조한다. 실제 화면 관찰과 수치 시험의 역할을 구분한다.

## 에이전트 지침·역할·스킬 검토

이 모드에서는 제품 코드가 없어도 운영 규칙을 검토할 수 있다. 역할 TOML·스킬 frontmatter 형식은 구조 검사 결과를 확인하고, 실제 배정 사례에서 다음을 판단한다.

- 작업에 맞는 스킬이 선택되고 필요한 참고 문서를 찾아갈 수 있는가.
- 수정 허용 범위와 공유 파일의 작성자가 명확하며 역할 사이에 빈 책임이나 충돌이 없는가.
- API 변경, 독립 기대값 오류, 실행 환경 없음과 저장 실패를 발견했을 때 적절한 책임자에게 반환하는가.
- 읽기 전용 역할이 수정·빌드·fixture 재생성을 요구받았을 때 제한을 유지하는가.
- 기술 실험·사용자 선택·완료 증거를 구분하며 모든 단계를 자동 승인하거나 반복 확인하는 규칙이 생기지 않았는가.
- 자동 발견, 역할별 런타임 권한, 현재 세션 로드와 파일 생성만을 근거 없이 동일시하지 않는가.

필요한 현실적인 배정 사례에 대해 수정 없이 행동을 설명한다. 예상 결론을 모르는 상태에서 자료와 규칙을 적용한다. 실제 수행하지 않은 행동이나 앱 시험은 검증했다고 보고하지 않는다.

## 발견과 반환

각 발견에 심각도, 파일/줄 또는 문서 절, 재현 조건, 기대/실제 동작, 영향과 근거, 연결된 요구사항·시험, 필요한 수정 또는 재검증을 적는다. 확인된 결함과 추정·검증 공백을 구분하고 표현 취향만으로 결함을 만들지 않는다.

빌드나 시험이 산출물을 쓰는 경우 메인에게 명령·환경·합격 기준을 반환한다. 읽기 전용 계산과 관찰은 가능하다. 중요 결함을 먼저 보고하고, 결함을 찾지 못했으면 실제 검토 범위와 남은 미검증 영역을 함께 반환한다.
