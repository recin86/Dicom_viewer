# 진행 기록과 AI 인수인계

현재 상태의 첫 화면은 [PROGRESS.md](../../PROGRESS.md)다. 이 디렉터리에는 실제 작업을 시작하면서 만든 단계 계획, 검증 증거와 인수인계 기록을 보관한다.

## 문서의 책임

| 문서 | 관리하는 내용 | 작성자 |
| --- | --- | --- |
| [PROGRESS.md](../../PROGRESS.md) | 현재 단계, 완료/진행/미착수, 활성 작업자·작성권, 다음 작업과 남은 조건 | 현재 조정 담당 AI |
| [work-log.md](work-log.md) | 날짜·task ID별 변경, 판단 근거, 실행 결과와 인수인계 이력 | 조정 담당 AI; 기존 기록은 보존 |
| `<단계>-<주제>.md` | 해당 단계의 작업 배정, 파일 작성권, 계약 revision, 시험 증거와 종료 판정 | 해당 단계의 조정 담당 AI |

단계 계획은 실제 착수할 때 [계획 양식](../../.agents/skills/dicom-orchestrate/assets/stage-plan.md)을 구체화한다. P0~P5의 비어 있는 완료 보고서를 미리 만들지 않는다. 현재 제품 단계 계획은 없다.

## 모든 AI의 작업 시작 절차

AGENTS.md의 자동 로드 여부는 도구마다 다를 수 있다. 다른 AI를 시작할 때도 다음 요청으로 공통 기준을 전달한다.

```text
이 폴더의 AGENTS.md와 PROGRESS.md, docs/implementation/README.md를 먼저 읽어줘.
실제 Git 상태와 진행 중인 작업을 확인하고, 기존 작성자의 변경을 보존하면서 다음 작업을 이어가줘.
중단하거나 완료할 때 진행 문서에 변경·검증·미해결 사항과 다음 작업을 남겨줘.
```

1. 현재 브랜치, HEAD, working tree 변경, 필요한 diff와 단계 계획을 확인한다. 문서의 날짜보다 Git/실제 파일이 새로우면 그 변경을 대조한다.
2. 활성 작업자와 겹치는 배정이 있는지 확인한다. 새 task ID와 AI/세션 식별자, 기준 commit, 목표, 허용 파일, 의존성과 상태를 단계 계획에 등록한다. 세션 식별자는 도구 이름이나 task ID면 충분하며 비밀·인증 정보는 넣지 않는다.
3. 단일 작업폴더의 중앙 진행 문서는 한 조정 담당자가 쓴다. 서브에이전트와 보조 AI는 결과를 조정 담당자에게 전달한다. 다른 독립 AI가 동시에 수정해야 하면 파일 작성권을 먼저 조정하거나 별도 브랜치/worktree를 사용한다.

문서의 작업자 표시는 동시 수정을 자동 차단하는 잠금이 아니다. 응답이 끊겼다고 이전 AI의 작업이 끝났다고 가정하지 않는다. 이전 작업자 상태와 실제 변경을 확인한 뒤 인수하고, 변경된 작성권을 기록한다.

## 작업 종료·중단 시 기록

각 기록에는 다음 정보를 남긴다.

- 날짜 (Asia/Seoul), task ID, 작성 AI/역할, 단계와 작업 상태.
- 기준 commit과 해당 변경을 찾는 방법. 커밋했으면 변경 commit을 기록할 수 있고, 자기 자신을 포함하는 커밋 해시를 문서에 억지로 넣지 않는다. 최신 commit은 실제 `git log`로 확인한다.
- 변경 파일과 사용자가 확인할 동작, 기술 결정의 이유와 관련 ADR.
- 실제 명령·환경·fixture·기대/실제 결과·증거 위치, `pass/fail/not-run/not-applicable`과 이유.
- 미커밋 파일·실행 중인 작업, 미해결 문제와 필요한 입력, 다음 작업·담당자·허용 경로.

해결되지 않은 작업은 paused/blocked와 이유를 기록하고, 일부 완료와 전체 완료를 구분한다. 단순히 문서를 갱신했다는 이유로 단계나 시험을 완료로 바꾸지 않는다. 관련 FR/QR·T ID와 정확한 기준은 기존 제품 문서에 연결한다.

변경과 검증 결과를 단계 계획·work log에 기록한 뒤 PROGRESS 요약을 맞춘다. 기존 이력을 삭제하거나 새 결론에 맞춰 다시 쓰지 않는다. 잘못된 기록은 정정 이력을 추가하고 현재 요약을 수정한다.

## Git 사용

로컬 기본 브랜치는 `main`이다. 원격 연결은 실제 `git remote -v`가 기준이다. 새 작업의 commit을 만들 때는 변경 범위를 확인하고 본인이 완료한 파일을 명시적으로 stage한다. 다른 AI의 진행 중인 변경을 함께 commit하거나 reset하지 않는다.

실제 원본 DICOM과 환자 자료는 로컬 자료 디렉터리에 두고 Git에 자동 추가하지 않는다. `.gitignore`는 일부 파일/경로만 거르므로 확장자 없는 DICOM이나 자유 메모의 식별 정보를 자동 감지한다고 가정하지 않는다. 시험 fixture는 사용·재배포 조건과 내용을 확인한 합성/재배포 가능한 경로에만 의도적으로 추가한다.

원격 저장소에 기존 이력이 있으면 연결 후 먼저 확인한다. 사용자 요청 없이 강제 push, 기존 브랜치 삭제, 공개 저장소 생성이나 다른 작성자의 기록 재작성을 하지 않는다.
